    Fleet XML reference¶

    Fleet XML is the only settings format qemu-tool reads. This page lists every element the parser knows. It is generated from the parser's own tables, as are the two schemas that go with it, so none of them can describe an element the parser does not have.

    qemu/stacks/rocm-golden.xml is the annotated example to copy or to lay an overlay on. qemu-tool check --xml FILE reports everything wrong with a file, and is the check that counts.

    The format¶

    A file is one <fleet> element in the namespace http://qemu-tool/fleet/1.0. Each setting is a child element whose text is the value, in any order:

    <fleet xmlns="http://qemu-tool/fleet/1.0">
  <vm-count>2</vm-count>
  <vm-name-prefix>rocm-golden</vm-name-prefix>
  <vm-vcpus>4</vm-vcpus>
</fleet>

    An element that is absent keeps its default. The parser is strict: an element it does not know, an element given twice, an attribute, a nested element and text directly under <fleet> are each an error. Comments are allowed. <devices> is the one element with attributes and children, and has a section of its own.

    --xml is repeatable, and a later file overrides the elements it sets. The schemas and this page describe one file.

    Value kinds¶

    Every setting has a kind, which is how the parser reads its text. White space here means what Python's str.strip() removes, which is more than a space, a tab and a line break.

    Kind The parser accepts The schemas check
    string (str) Any text, kept as written, surrounding white space included. An empty element is the empty string. Nothing: any text.
    path (expand) Any text. ~ and $VARS are expanded when the file is parsed, so every command sees the same path. Nothing: any text.
    command-line words (args) Words as a shell would split them: quotes group and are removed, nothing is expanded. An unclosed quote, a control character and a word that spans lines are errors. That it holds no control character (U+007F, U+0085, U+2028 or U+2029). Quoting is not something a grammar can check: an unclosed quote, a trailing backslash and a quoted word that spans lines pass the schema.
    boolean (bool) true, false, 1, 0, yes or no, in any letter case, with no white space round it. An empty element is an error. The same six words in any case, exactly.
    integer (int) What Python's int() takes in base 10: an optional sign, decimal digits, single underscores between digits, white space round the whole. An empty element is an error. No range is checked here; the command that reads the value may check one. The same form, with one difference: any character outside ASCII that is not white space passes as a digit. Which characters are decimal digits depends on a Unicode version, and a validator's is not Python's, so the schema does not ask. Nor does it count: an integer of more digits than int() converts (4300 unless Python is told otherwise) passes the schema and not the parser. An integer with thousands of underscores can stop a Java validator; see below.
    port (port) A port number from 1 to 65535 in ASCII digits, or the word auto in any case; white space round it is ignored. The same form, range included. A number of more digits than Python's int() converts, which takes thousands of leading zeros, passes the schema and not the parser.
    address (addr) An IPv4 or IPv6 literal, with or without square brackets, with no zone and no host name. Empty, or white space alone, is the default. The same form: octets of 0 to 255 with no leading zero, groups of one to four hexadecimal digits, one :: at most, brackets in pairs.
    CPU vendor (vendor) Exactly 12 printable ASCII characters (space to ~) with no comma, such as AuthenticAMD or GenuineIntel, kept as written with no white space stripped; or an empty element, which is a value of its own (state no vendor) and not the default. The same form, exactly.
    block size (blocksize) 512 or 4096, a number of bytes in ASCII digits; white space round it is ignored. No sign, no underscore, no leading zero and no unit. An empty element is an error. The same form, exactly.
    MTU (mtu) A number of bytes from 1500 to 9198 in four ASCII digits; white space round it is ignored. No sign, no underscore, no leading zero and no unit. An empty element is an error. The same form, range included.

    Elements¶

    Default is the value when the element is absent; (empty) is the empty string, and for many elements the command that reads it then applies a default of its own, which the description gives. Sparse elements are left out when FleetXml.emit() writes a configuration back out as XML and the value is an empty string, zero or false; no command calls it today, so the column matters to code that does.

    Shape¶

    How many guests a fleet has, what they are called and where their SSH ports go.

    Element Kind Default Sparse Description
    <vm-count> integer 1 no Number of guests in the fleet; each gets its own QEMU service and its own set of device servers. Integer, at least 1 (render exits below that), default 1. Baked into the generated compose file, so a change means re-rendering. Bounded by 64 mesh NICs (warning above 40) and 244 NICs in total.
    <vm-name-prefix> string qemu-fleet no Prefix of every guest's name; guest N is <prefix>-N, the name run-vm passes on for the guest's hostname. String, default qemu-fleet. gen-compose takes the default for an empty element; quick-start does not, and looks for guests named -1, -2. Names run from <prefix>-1. The guest lower-cases it and turns characters outside a-z, 0-9 and - into hyphens for its hostname.
    <ssh-port-base> integer 2222 no Host port published for guest 1's SSH; guest N gets the base plus N minus 1. Integer, default 2222; kind is int, so auto is a parse error. Published on <publish-bind-addr> to container port 2222. quick-start moves the range in an overlay of its own when a port is taken.
    <stop-grace-period> string 120s no How long docker waits after asking a guest's QEMU container to stop before it kills it. Compose duration such as 120s (the default); passed through as text, not validated by the parser; empty takes the default. Applies to the qemu-N services only. QEMU exits on SIGTERM without shutting the guest down, so this does not make a stop graceful.

    Images¶

    The container images a stack runs and the guest disk image its guests pull.

    Element Kind Default Sparse Description
    <qemu-ref> string (empty) yes Container image that runs QEMU for each guest; must share a build stamp with the ernic and rocjitsu images. Image reference, repository:tag; required (an empty one stops the render). A tag with no <date>.g<sha> stamp is warned about and left out of the comparison. A repository ending -sbates-fork is taken as the fork QEMU, which <vm-nvme-vram>, <vm-pci-mmio-bridge> and dma-buf RDMA need.
    <ernic-ref> string (empty) yes Container image of the rocm-ernic server that emulates each RDMA NIC; same build stamp and vfu.<sha> as QEMU. Image reference, repository:tag; required. The render compares the stamp and the vfu.<sha> part of the tag with <qemu-ref>'s. That its ernic.<sha> matches the guest's driver commit is held by tests/test_playbook_pins.py, not by the render.
    <rocjitsu-ref> string (empty) yes Container image of the rocjitsu server that emulates each GPU; same build stamp as the QEMU and ernic images. Image reference, repository:tag; required (an empty one stops the render).
    <sdxi-image> string (empty) yes Container image of the SDXI device server; required when a guest has an SDXI device. Image reference, repository:tag. Needed when <sdxi-per-vm> is non-zero or <devices> has a server of type sdxi. Not compared with the servers' stamp by the render; its sdxi.<sha7> against the guest's driver commit is a test's check.
    <spdk-image> string (empty) yes Container image of the SPDK vfio-user NVMe controller; required when <devices> has a server of type spdk. Image reference, repository:tag. Its vfu.<sha> must equal the one in <qemu-ref>, stamped tag or not. Nothing runs it without a spdk entry in <devices>.
    <backing-ref> string (empty) yes Published guest disk image that gen-vm and quick-start pull as each guest's backing file. OCI reference by dated tag YYYYMMDD.g<sha7> or name@sha256:...; empty pulls nothing. gen-compose refuses no tag, latest, qm.<sha7> and near misses of those, and, in the repository <publish-ref> names, any tag but the dated one. Any other tag must share the servers' stamp, or is warned about if unstamped. gen-vm --bake ignores it.

    Network¶

    The docker network every service's address is derived from. The guests' RDMA NIC network, 192.168.100.0/24, and the first four bytes of each emulated NIC's MAC address, 72:6f:63:6d, are fixed: the guest image assumes the first and the quick-start playbook the second.

    Element Kind Default Sparse Description
    <fleet-prefix> string 172.31 no First two octets of the stack's docker network; every service gets a fixed address under it. Two dotted octets, default 172.31; not validated by the parser, empty takes the default. Third octet is the service family: 0 infra, 1 ernic, 2 rocjitsu, 3 qemu, 4 sdxi, 5 spdk; the last is the device's number.

    Topology¶

    How many emulated devices each guest gets, and where they sit on its PCIe bus.

    Element Kind Default Sparse Description
    <ernic-per-vm> integer 1 no Emulated RDMA NICs per guest; each is its own mesh node, so it multiplies against the mesh's node ceiling. Integer, at least 1, default 1. Fleet total is refused above 64 mesh nodes or 244 NICs and warned about above 40. Replaced by the <devices> block when one is given.
    <rocjitsu-per-vm> integer 1 no Emulated GPUs per guest, each served by its own rocjitsu server. Integer, at least 1, default 1. Replaced by the <devices> block when one is given.
    <sdxi-per-vm> integer 0 yes SDXI devices per guest; 0 gives none, and above 0 needs <sdxi-image>. Integer, default 0. Replaced by the <devices> block when one is given.
    <vm-pcie-switch-width> integer 0 no Put each guest's vfio-user devices below PCIe switches, this many devices per switch; 0 leaves them on root ports. Integer, default 0 (off). Devices are ordered NICs-per-GPU NICs then one GPU, so 2 with equal counts gives one NIC and one GPU per switch, and 3 with twice as many NICs gives two NICs and a GPU. Rendered as run-vm --vfio-user-switch-width; run-vm refuses a negative value.

    ERNIC¶

    Settings of the rocm-ernic servers: the TAP, the mesh, statistics and the P4 engine.

    Element Kind Default Sparse Description
    <ernic-tap> boolean false no Give each ernic NIC a TAP on a shared L2 network so guests have Ethernet; inter-guest RDMA tests need it. true or false; default false. Adds one tapsetup sidecar per NIC and the l2 network.
    <ernic-mtu> MTU 1500 no MTU of every guest's emulated ernic NICs and of the Ethernet between guests; 4192 up gives RDMA an active_mtu of 4096. 1500 to 9198, in bytes; default 1500, the device's own, which renders nothing. Anything else is a parse error. The guest's RDMA active_mtu follows the NIC: 1024 below 2144, 2048 below 4192, 4096 from there. Each guest is handed a udev rule at boot through a systemd credential (QEMU -smbios type=11), which the guest's systemd has to load (systemd-udev-load-credentials; the published image does); with ernic-tap true the l2 network and every tap are created at the same MTU. A running stack does not take a changed value: bring it down and up. Generated stacks only, run-vm --xml does not get it.
    <ernic-tcp-port> integer 6320 no TCP port the ernic mesh manager listens on and the workers dial; the mesh health checks match it. port number; default 6320. Used by mesh NICs only; a NIC with its own backend ignores it.
    <ernic-stats-port> integer 9840 no Port the ernic stats exporter serves on, and the port Prometheus scrapes it at. port number; default 9840; inside the stack network, not published on the host.
    <ernic-nofile> integer 65536 no Open file descriptor limit for every ernic server; Docker's default of 1024 is too low for a mesh manager. count, written as both the soft and the hard nofile ulimit; default 65536.
    <p4-enable> boolean false no Run the P4 engine (--p4) on every ernic server; quick-start --p4-test needs it true. true or false; default false. When false, p4-guest-scope and p4-program are not rendered.
    <p4-guest-scope> string none no Which guest P4 commands reach the engine: none, read counters, write table entries, or load a program. none, read, write or load, each including the ones before it; default none. Unchecked: any other word is passed to the server. Only with p4-enable; --p4-test needs load.
    <p4-program> string (empty) no Path inside the ernic container of a bmv2 JSON program loaded at start; empty leaves the engine in pass-through. a path inside the ernic container, not on the host; default empty; only rendered with p4-enable true.

    VM defaults¶

    What every guest is given. gen-vm and run-vm take most of these as the defaults of their flags; <vm-pci-mmio-bridge> and <rocjitsu-config> are read by the generator alone, <vm-nvme-vram> by the generator and by quick-start, for its --hipfile-test note, and <vm-shm-size> by the generator and by quick-start, for its /dev/shm warning.

    Element Kind Default Sparse Description
    <vm-vcpus> integer 0 no vCPUs per guest; keep it at 4 or more on an ernic stack, and vCPUs times guests near the host's core count. integer; 0 or unset leaves run-vm's default of 2; qemu-tool check FAILs a value set from 1 to 3 and does not check 0 or unset; quick-start by default (not with --no-size-from-host) replaces it with a host-derived value (floor 4, ceiling 8).
    <vm-vmem> integer 0 no Guest memory per VM. MiB (4096 is 4 GiB); 0 or unset leaves run-vm's default of 4096; quick-start by default (not with --no-size-from-host) replaces it with a host-derived value (floor 4096, ceiling 8192).
    <vm-shm-size> string 8g no shm_size of each guest's qemu container; must be at least vm-vmem or QEMU cannot allocate guest RAM. docker size such as 8g or 5120m; one value for all guests, or a comma list of exactly vm-count values; empty or unset is 8g. quick-start by default (not with --no-size-from-host) sets it to vm-vmem plus 1024m.
    <vm-nvme> integer 0 no Number of emulated NVMe scratch devices per guest; run-vm creates a qcow2 for each. 0 gives none. integer; N > 0 is N devices on scratch qcow2 files; -N is N devices on the host's /dev/nullb0.. (null_blk); default 0.
    <vm-nvme-vram> boolean false yes Point each guest's emulated NVMe at its first GPU's BAR 0 (VRAM) so hipFile direct reads are fast; fork QEMU only. true or false; default false; refused with vm-nvme of 0 or less; warns on a non-fork qemu-ref; generated stacks only, run-vm --xml does not get it.
    <vm-nvme-block-size> block size 512 no Logical and physical block size of each guest's emulated NVMe namespaces: the LBA format the guest sees in use. 512 or 4096, in bytes; default 512, QEMU's own, which renders nothing. Anything else is a parse error. Refused at 4096 with vm-nvme of 0. QEMU's emulated NVMe only: an SPDK controller and an nvmeof backend set their own. Nothing on the scratch disk is converted: a partition table made at one size is not found at the other, and XFS or ext4 with blocks under 4096 made at 512 does not mount at 4096.
    <vm-pci-mmio-bridge> boolean false yes Give every guest the fork QEMU's pci-mmio-bridge device for its emulated NVMe, which rocm-xio uses. true or false; default false; refused with vm-nvme of 0 or less; needs the fork QEMU; generated stacks only, run-vm --xml does not get it.
    <vm-username> string ubuntu no Guest login account: the user gen-vm creates, and the one the inventory, quick-start and ssh log in as. default ubuntu; dropped for gen-vm --bake (bake-username is used); quick-start overrides it with the pulled image's own account when they differ.
    <vm-password> string (empty) no Password of the account gen-vm creates from the cloud image; never reaches a pulled guest, and a bake drops it. plain text; empty or unset leaves gen-vm's default, which is the word password.
    <vm-filesystem> string (empty) no Host directory shared into each guest over 9p with mount tag hostfs. one host path for all guests, or a comma list of exactly vm-count paths; run-vm --xml outside a stack ignores a list; default empty, no share.
    <vm-vfio-user-root-port> boolean true no Put each vfio-user device behind a PCIe root port; off, an emulated GPU gets a 16M 32-bit BAR amdgpu cannot use. true or false; default true; false renders with a warning, not an error.
    <vm-extra-hostfwd> string (empty) no Extra QEMU host-forward rules; every rule goes to every guest, and a bake leaves them out. Comma list of QEMU hostfwd rules, e.g. tcp::9100-:9100,tcp::9879-:9879; items are stripped and empty ones dropped. The commas are several rules for ONE guest, not one rule per guest.
    <vm-qemu-args> command-line words (empty) yes Extra words appended as they are to every guest's QEMU command line; nothing validates them. Words split as a shell would (quotes group, nothing expands), e.g. -device pci-testdev -d guest_errors; an unclosed quote is a parse error. One value for the whole fleet; a later layer replaces it whole. Dropped for a bake.
    <vm-ssh-key-file> path (empty) no Public key gen-vm authorises in a guest it creates, bakes included; ssh and inspect fall back to it. Path to a .pub file; ~ and $VARS are expanded at parse time. Unset, a bake generates a keypair for the image. Never the key publish-qcow publishes.
    <vm-images-dir> path /var/lib/qemu-tool/images no Directory that holds the guest disk images, overlays and image keys; --images overrides it. Path; ~ and $VARS are expanded at parse time. Default /var/lib/qemu-tool/images. Reaches docker compose as VM_IMAGES_DIR.
    <vm-cpu-sockets> integer 0 yes Pin each guest's CPU socket count; unset, the guest sees one single-core socket per vCPU. Integer that must divide the guest's vCPU count (run-vm exits otherwise); 0 or unset leaves the topology to QEMU.
    <vm-cpu-phys-bits> integer 0 yes Physical address bits of each guest's CPU; raise it together with vm-pci-hole64-size for large GPU BARs. Integer number of bits, e.g. 42; amd64 only (added to -cpu as phys-bits=N). 0 or unset passes no phys-bits; run-vm's help gives that default as 40 (1 TiB).
    <vm-cpu-vendor> CPU vendor AuthenticAMD no CPUID vendor every guest's CPU states; a guest is an AMD machine on every host unless this says otherwise. Exactly 12 printable ASCII characters with no comma, such as AuthenticAMD or GenuineIntel, or empty; default AuthenticAMD. amd64 only (rendered as -cpu EPYC,vendor=...). An EMPTY element is not the default: it states no vendor, and under KVM the guest then has the host's. Anything but AuthenticAMD renders with a note: the guest kernel refuses P2PDMA between devices that share no upstream bridge unless the CPU is AMD.
    <vm-pci-hole64-size> string (empty) no Size of each guest's 64-bit PCI hole; needed when several large GPU BARs exceed the machine default. QEMU size such as 512G or 1024G, passed through unparsed as q35-pcihost.pci-hole64-size; empty leaves the machine default.
    <rocjitsu-config> string gfx1250_mi455x.json no rocjitsu simulation config that selects the GPU each guest's emulated GPU servers present. File name under /usr/local/share/rocjitsu/configs in the rocjitsu image, default gfx1250_mi455x.json. One value for all guests, or a comma list of exactly vm-count values; a <devices> entry's own config wins.

    Misc¶

    Settings that belong to no other group.

    Element Kind Default Sparse Description
    <qemu-tool-src> string ../../.. no Checkout the stack's containers mount to build qemu-tool from; with none there they install it from PyPI. Path, default ../../.. relative to the stack directory; use an absolute path for a stack rendered elsewhere. Reaches docker compose as QEMU_TOOL_SRC and is not baked into the render. ~ is not expanded (plain string kind).
    <image-allow-guest-lag> boolean false no Let the guest image be older than the device server images: skips that check and warns on every render. Boolean (true/false, 1/0, yes/no), default false. Does not excuse a moving tag (latest, qm.<sha7>) or a malformed one, which are refused before it is looked at.

    Bake and publish¶

    Read by gen-vm --bake, publish-qcow --xml and publish-qcow-prune --xml and by nothing else, but for <publish-ref>, which gen-compose reads as well.

    Element Kind Default Sparse Description
    <bake-name> string (empty) yes Name of the image gen-vm --bake builds; publish-qcow publishes the image of that name. VM name; the baked image is <vm-images-dir>/<name>-backing.qcow2.
    <bake-release> string (empty) yes Ubuntu release of the cloud image gen-vm --bake starts from; publish-qcow records it for the image. Ubuntu codename (resolute) or version (26.04); publish-qcow records resolute when unset.
    <bake-size> integer 0 yes Virtual disk size of the image gen-vm --bake builds. Integer, GiB: passed to qemu-img resize as <n>G (the --size help calls it GB). 0 or unset leaves gen-vm's default.
    <bake-vcpus> integer 0 yes vCPUs of the guest gen-vm --bake boots to build the image; not the size of a fleet's guests. Integer count; a bake is refused unless bake-vmem is at least 1024 MiB per vCPU. 0 or unset falls back to vm-vcpus, then gen-vm's default.
    <bake-vmem> integer 0 yes RAM of the guest gen-vm --bake boots to build the image; not the size of a fleet's guests. Integer, MiB; must be at least 1024 per bake vCPU or the bake is refused. 0 or unset falls back to vm-vmem, then gen-vm's default.
    <bake-packages> path (empty) yes Package manifest gen-vm --bake installs in the image, or none for no manifest. Path to a manifest file, resolved against the current directory (run from the checkout root); ~ and $VARS are expanded. The word none installs none; a missing file stops the bake before it starts.
    <bake-playbook> path (empty) yes Ansible playbook gen-vm --bake runs against the booted image; publish-qcow records it for the image. Path resolved against the current directory (run from the checkout root); ~ and $VARS are expanded. publish-qcow records it as given, empty when unset.
    <bake-username> string (empty) yes Login account baked into the image and published with it; separate from vm-username, with no fallback. User name; unset, the bake uses gen-vm's default account and publish-qcow records ubuntu.
    <bake-password> string (empty) yes Password of the baked account; published with the image, so it is public. Never vm-password. Plain text, written to the published vm-info.json; publish-qcow records password when unset.
    <bake-ssh-port> port (empty) yes Host port the bake's Ansible boot forwards to the guest's sshd; auto picks a free one from 2222 up. A port number, or the word auto.
    <bake-cache-dir> path (empty) yes Directory on this host that keeps the bake's compiler cache between bakes; --cache-dir wins, unset is none. Path; ~ and $VARS are expanded. Needs a bake-playbook, which gets it as the extra var bake_cache_dir. Per host: set it in a local overlay, not in a shipped fleet file.
    <publish-ref> string (empty) yes Repository publish-qcow pushes to and publish-qcow-prune prunes; tells gen-compose whose repo backing-ref is in. Image repository with no tag, e.g. docker.io/sbates130272/qemu-tool-rocm-golden; publish-qcow appends :<tag> from each --tag. Read by the two publish commands only from an explicit --xml.
    <publish-flavour> string (empty) yes Label publish-qcow records in the published artifact for what kind of guest the image is. Free-form name, written to vm-info.json, the vm.flavour annotation and the description; rocm-golden when unset.

    Metrics¶

    Prometheus, Grafana and the address a stack's ports are published on.

    Element Kind Default Sparse Description
    <publish-bind-addr> address 127.0.0.1 no Host address every guest SSH port and the Grafana port are published on; loopback keeps them to this host. IPv4 or IPv6 literal, brackets optional and dropped, no host name or zone; empty or unset means 127.0.0.1; 0.0.0.0 or :: exposes every interface. Also decides ansible_host in the generated inventory.
    <prom-scrape-interval> string 15s no How often Prometheus scrapes the stack's exporters; written as the global scrape_interval of prometheus.yml. Prometheus duration such as 15s; not validated by the parser; empty or unset means 15s.
    <prom-retention> string 7d no How long Prometheus keeps collected metrics; passed as --storage.tsdb.retention.time. Prometheus duration such as 7d; not validated by the parser; empty or unset means 7d.
    <prom-data-dir> path (empty) yes Host directory bind-mounted as the Prometheus database; compose up creates it owned by the caller. Host path, ~ and $VARS expanded at parse time; unset means /var/lib/qemu-tool/prom-data; quick-start with metrics on overrides it to <stack-dir>/prom-data.
    <grafana-enable> boolean true no Add a Grafana service with the fleet dashboards to the stack; it starts only with --profile metrics. true/false, also 1/0/yes/no, any case; default true. Prometheus is rendered either way.
    <grafana-image> string docker.io/grafana/grafana:latest no Container image the Grafana service runs. Image reference; empty or unset means docker.io/grafana/grafana:latest (a moving tag).
    <grafana-port> integer 3000 no Host port Grafana is published on, at publish-bind-addr; quick-start moves it when the port is busy. Integer port (kind int, no range check); default 3000; container side is always 3000.
    <grafana-admin-password> string admin no Password of Grafana's admin account; anonymous admin access is on regardless, so it guards nothing. Plain text, written into the generated docker-compose.yml as GF_SECURITY_ADMIN_PASSWORD; empty or unset means admin.
    <grafana-data-dir> path (empty) yes Host directory bind-mounted as Grafana's own state (its sqlite); dashboards are provisioned from files. Host path, ~ and $VARS expanded at parse time; unset means /var/lib/qemu-tool/grafana-data; quick-start with metrics on overrides it to <stack-dir>/grafana-data.

    Logging¶

    Log rotation for every service, and the Loki and Alloy log collection.

    Element Kind Default Sparse Description
    <log-max-size> string 50m no Size at which Docker rotates each service's json-file log, so a looping service cannot fill the disk. Docker size string such as 50m; not validated by the parser; empty or unset means 50m.
    <log-max-files> integer 3 no Number of rotated log files Docker keeps for each service. Integer count (no range check); default 3.
    <logs-enable> boolean true no Add Loki and an Alloy that ships the stack's container logs to it; both start only with --profile metrics. true/false, also 1/0/yes/no, any case; default true. Alloy mounts the Docker socket and runs as root.
    <loki-image> string docker.io/grafana/loki:3.3.2 no Container image the Loki log store runs; used only with logs-enable. Image reference; empty or unset means docker.io/grafana/loki:3.3.2.
    <loki-data-dir> path /var/lib/qemu-tool/loki-data no Host directory bind-mounted as Loki's stored logs; used only with logs-enable; compose up creates it as the caller. Host path, ~ and $VARS expanded at parse time; empty or unset means /var/lib/qemu-tool/loki-data; quick-start with metrics on overrides it to <stack-dir>/loki-data.
    <alloy-image> string docker.io/grafana/alloy:v1.5.1 no Container image of the Alloy agent that ships the stack's container logs to Loki; used only with logs-enable. Image reference; empty or unset means docker.io/grafana/alloy:v1.5.1.

    Removed elements¶

    These were elements of the format and are not any more. Most were parsed and read by no command; the table says what to do about the ones that were read. A file that sets one is refused by the parser, which says so by name, and by both schemas, to which it is an unknown element like any other:

    Element Why it went
    <qemu-digest> No command ever read it, so it never pinned <qemu-ref>.
    <ernic-digest> No command ever read it, so it never pinned <ernic-ref>.
    <rocjitsu-digest> No command ever read it, so it never pinned <rocjitsu-ref>.
    <backing-digest> No command ever read it, so it never pinned <backing-ref>; to pin the guest image by digest, write name@sha256:... in <backing-ref>.
    <domain-pattern> No command ever read it, and no command writes or reads a per-guest domain file for a fleet.
    <prom-port> No command ever read it; Prometheus has no host port and is asked inside its container.
    <loki-port> No command ever read it; Loki has no host port and listens on 3100 inside the stack.
    <vm-backing-shared> A generated stack always starts its guests with image locking off, whatever this said; for a run-vm outside a stack, pass --backing-shared.
    <ernic-subnet> The guests' RDMA NICs are always on 192.168.100.0/24, the one network the guest image addresses them on at boot, so any other value put the fleet's addresses where no guest was.
    <ernic-mac-prefix> Every emulated NIC's MAC address always starts 72:6f:63:6d, the one prefix the quick-start playbook finds a guest's NIC by, so any other value failed that playbook. 
    my-fleet.xml: <prom-port> was removed from the fleet format: no command ever read it; Prometheus has no host port and is asked inside its container. Delete the element.

    The devices block¶

    <devices> lists the vfio-user servers every guest gets, one <server> entry each. It exists so that two servers of one type can differ, and so that a NIC can be given an RDMA backend.

    <devices>
  <server type='ernic' id='kv'>
    <backend type='nvmeof'>kv=1,size=256M</backend>
    <log-level>info</log-level>
  </server>
  <server type='ernic' id='mesh'/>
  <server type='rocjitsu' id='gpu0'>
    <cpu-thread-budget>2</cpu-thread-budget>
  </server>
  <server type='sdxi' id='sdxi0'/>
</devices>
    Part Description
    <devices> Lists the vfio-user servers every guest gets, one <server> each; replaces the three per-VM device counts. No attributes, no text; at least one <server>. Later layers merge entries by id, append new ids and cannot remove one. Every guest gets the same list.
    <server> One device server every guest gets; its children set that server's backend, config file or options. Requires type and id, and takes no other attribute. Children allowed depend on type; each may appear once unless the option is repeatable.
    <server type=...> Kind of server: an ernic NIC, a rocjitsu GPU, an SDXI device or an SPDK NVMe controller. ernic, rocjitsu, sdxi or spdk. The generator refuses more than one spdk a guest, and an spdk with no <spdk-image>. An id cannot change type in a later layer.
    <server id=...> Names the entry for later layers to merge on and for error messages; does not rename containers or sockets. Starts with a letter; letters, digits, '_', '.' and '-'; 32 characters at most; unique in the block.

    The children of a <server> depend on its type. They may come in any order. A value is stripped of surrounding white space, may not be empty and may not hold a line break, a tab or a control character.

    Servers of type ernic¶

    Element Shape Becomes Description
    <backend> attribute type, options as text, at most once -b TYPE or -b TYPE:OPTIONS Sets an ernic NIC's RDMA backend; any type but tcp takes that NIC out of the generated TCP mesh. ernic only. Text is the backend's own options, optional, as one word with no whitespace: size=1G,ns=2,kv=1,size=256M. The parser checks only that; tcp takes none.
    <log-level> one value, at most once --log-level VALUE Log verbosity of this NIC's server. none, error, warn, info or debug; the server's default is warn. The parser does not check the word.
    <nic-profile> one value each, repeatable, order kept --nic-profile VALUE Shapes the NIC from a profile; repeatable, and later profiles win. A built-in name (compat, small-vm, generic-100g, generic-400g) or a path to an ini file inside the server container. Repeatable, order kept; a later layer naming it replaces all earlier values.
    <stats-interval-ms> one value, at most once --stats-interval-ms VALUE How often the server rewrites the guest's statistics; overrides every profile. Milliseconds, 10 to 60000; the server's default is the profile's, 1000. The parser does not check the number or range.
    <eth-queues> one value, at most once --eth-queues VALUE Number of Ethernet Rx/Tx queues the NIC offers the guest; overrides every profile. Integer 1 to 64; the server's default is the profile's, 4. The guest uses at most one per vCPU. The parser does not check the number or range.
    <inject> one value each, repeatable, order kept --inject VALUE Injects a fault into this NIC's server, for testing; repeatable. One fault as 'SITE: PATTERN effect EFFECT', for example 'stats_vals: every 100 effect fail status eio'. Spaces allowed. Repeatable, order kept; unchecked by the parser.

    Servers of type rocjitsu¶

    Element Shape Becomes Description
    <config> one value, at most once the server's config file Names the rocjitsu simulation config file for this one GPU, in place of <rocjitsu-config>. rocjitsu only. One file name in the image's configs directory, no path: starts with a letter or digit, then letters, digits, '.', '_', '-'. Example gfx1250_mi455x.json.
    <node> one value, at most once --node VALUE Selects one local node from a rocjitsu system manifest; needed for a multi-node launch. A node name from the manifest the config file refers to; unchecked by the parser.
    <cpu-thread-budget> one value, at most once --cpu-thread-budget VALUE Overrides the CPU thread budget of this GPU's server; zero selects automatic sizing. Integer count of threads; 0 is automatic. The parser does not check that it is a number.
    <wait-checking> one value, at most once --wait-checking VALUE Overrides this GPU server's wait checks. off disables checks, on enables ordinary checks, all adds the gfx1250 XCNT checks. The parser does not check the word.

    Servers of type sdxi¶

    Element Shape Becomes Description
    <verbose> empty element, repeatable --verbose Raises the SDXI server's log verbosity; repeat it for debug output. A switch: empty element, no value, no attributes. May be repeated; each occurrence renders one --verbose.

    Servers of type spdk¶

    Element Shape Becomes Description
    <namespaces> one value, at most once NVME_NAMESPACES=VALUE in the container's environment The namespaces the SPDK NVMe controller serves, in order; sets the image's NVME_NAMESPACES. One word, comma list, NSIDs in list order: lba:malloc:SIZE[:BLOCK], lba:aio:PATH[:BLOCK[:SIZE]], kv:mem[:MAXVAL[:MAXKEYS]]. Image default lba:malloc:512M,kv:mem.
    <serial> one value, at most once SPDK_SERIAL=VALUE in the container's environment Serial number of the SPDK NVMe controller, as the guest sees it; sets the image's SPDK_SERIAL. 1 to 20 letters, digits, '_' and '-'. Image default SPDKVFU01.
    <cpumask> one value, at most once SPDK_CPUMASK=VALUE in the container's environment Host cores the SPDK server's poll-mode reactor spins on; sets SPDK_CPUMASK. Each server takes one full core. Hexadecimal core mask, 0x then 1 to 32 hex digits, such as 0x4. Default 0x1, host CPU 0. One value for every guest's server, so guests share the cores it names.

    Backend types¶

    The type attribute of <backend>. The element's text is the backend's own options as one word; the parser checks that it has no white space and that tcp has none, and nothing else about it.

    Type Description
    none No RDMA backend: the server runs minimal stubs and the NIC is off the mesh. No options in the server's help; the parser still accepts option text and passes it on as none:TEXT.
    loopback The server's internal loopback emulation, for a guest with no peer; the NIC is off the mesh. No options in the server's help; the parser does not refuse text.
    tcp The generated TCP mesh between guests; the same as naming no backend. Takes no options, and text is an error: manager, workers and addresses are derived.
    nvmeof An NVMe-oF target inside the NIC's server that the guest reaches with nvme connect over RDMA; off the mesh. Comma options, order dependent: size=, file=, bs=, nqn=, ip=, port=, queues=, kv=1, keys=, maxval=, nsid=; ns=N starts the next namespace. Sizes take K/M/G/T; default 64M.
    s3 An S3-over-RDMA object store inside the NIC's server that the guest reaches over HTTP; off the mesh. Comma options: bucket= (default ernic), size= with K/M/G (default 256M), objects= (default 256), ip= (default 192.168.200.1), port= (default 9000), maxpart= (default 256M).

    The schemas¶

    There are two, generated from the same tables and with the same patterns:

    Schema Language Use it
    fleet.rng RELAX NG, XML syntax, with XML Schema datatypes for the patterns Wherever the tool takes RELAX NG. It is the precise one: it says everything about one file that a grammar can.
    fleet.xsd XML Schema (XSD) 1.0 With an editor or a tool that takes only XSD. It is looser, and not only inside <devices>.

    Neither rejects a file the parser accepts, and the XSD rejects no file the RELAX NG schema accepts. Each is one file:

    • qemu/schema/fleet.rng and qemu/schema/fleet.xsd in a checkout,
    • /usr/share/qemu-tool/schema/fleet.rng and /usr/share/qemu-tool/schema/fleet.xsd, installed by the Debian package and by nothing else,
    • qemu_tool/share/schema/ inside the wheel, which a uv tool install or pipx install puts in an environment of its own, at no path worth typing,
    • or written on demand, which works from any install: qemu-tool fleet-schema --output fleet.rng and qemu-tool fleet-schema --format xsd --output fleet.xsd. The examples below use copies written that way.

    They are generated, and so is this page. After a change to the tables in qemu/qemu-tool/fleet_xml.py, from the root of a checkout:

    qemu-tool fleet-schema --format rng --output qemu/schema/fleet.rng
qemu-tool fleet-schema --format xsd --output qemu/schema/fleet.xsd
qemu-tool fleet-schema --format md --output docs/fleet-xml.md

    The XSD is written by qemu-tool from the tables, not converted from the RELAX NG file. trang, the usual converter, does convert fleet.rng, with two warnings that it is approximating. What it writes is neither stricter nor looser than fleet.xsd throughout. It takes more: a flat setting, the <devices> block and a once-only child of a <server> may repeat, and every element is declared globally, so any of them passes as the root of a document. And it takes less in one place: it types a string or a path setting as xs:string and declares no kind.str or kind.expand, so an xsi:type naming either, which fleet.xsd accepts on such a setting, is refused by trang's.

    Where the XSD is looser¶

    The XSD accepts everything the RELAX NG schema accepts, and these besides. This is the whole list: the test suite has a document for each item that RELAX NG refuses and the XSD takes, and requires the two to agree on every other document it holds.

    • An attribute XML Schema reserves for itself passes: xsi:schemaLocation and xsi:noNamespaceSchemaLocation on any element, with any value, and xsi:type on a flat setting when it names the type that setting already has. The RELAX NG schema refuses them, as the parser does: no element but <server> and <backend> takes an attribute.
    • A <server>'s children are held to the children of one type, which need not be the type its type attribute names: XSD 1.0 cannot make an element's content depend on an attribute's value. <config> in a server of type ernic passes. Children of two types in one server are still refused. The sets are <backend>, <log-level>, <nic-profile>, <stats-interval-ms>, <eth-queues>, <inject> (ernic); <config>, <node>, <cpu-thread-budget>, <wait-checking> (rocjitsu); <verbose> (sdxi); <namespaces>, <serial>, <cpumask> (spdk).
    • <backend type='tcp'> may hold option text, as the other backend types do. tcp takes none, and XSD 1.0 cannot make an element's text depend on an attribute's value.

    Everything else is the same in both: the flat settings, each at most once and in any order; the value kinds; the server types and ids; the backend types; the form of each option's value; and, in a <server>, that a child which may appear once does not appear twice.

    Validating a file¶

    qemu-tool check --xml FILE runs the parser itself and is the answer that counts. A schema is for tools that do not have qemu-tool: an editor, a CI step, another program that writes fleet files.

    With xmllint, from libxml2:

    qemu-tool fleet-schema --output fleet.rng
xmllint --noout --relaxng fleet.rng my-fleet.xml

qemu-tool fleet-schema --format xsd --output fleet.xsd
xmllint --noout --schema fleet.xsd my-fleet.xml

    With lxml, in Python:

    from lxml import etree

document = etree.parse("my-fleet.xml")

rng = etree.RelaxNG(etree.parse("fleet.rng"))
if not rng.validate(document):
    print(rng.error_log)

xsd = etree.XMLSchema(etree.parse("fleet.xsd"))
if not xsd.validate(document):
    print(xsd.error_log)

    With jing, a RELAX NG validator that is not libxml2. It takes the RELAX NG schema only:

    jing fleet.rng my-fleet.xml

    xmllint and lxml both use libxml2. Its messages name the element it stopped at and little else; the parser's say what is wrong and suggest the closest known name.

    Editors¶

    A fleet file cannot name its schema in an attribute. The usual way to point at an XSD is xsi:schemaLocation on the root element, and the parser refuses it, as it refuses any attribute on <fleet>:

    my-fleet.xml: <fleet> takes no attributes, found {http://www.w3.org/2001/XMLSchema-instance}schemaLocation

    The XSD itself would accept the attribute, which is the first item of the list above; the file would validate in the editor and not load. So the association is made outside the element, in one of two ways.

    In the editor's settings, which leaves the fleet file alone. For the XML extension of VS Code (redhat.vscode-xml), in settings.json, with the pattern and the path changed to suit:

    {
  "xml.fileAssociations": [
    {
      "pattern": "**/fleet*.xml",
      "systemId": "/path/to/fleet.xsd"
    }
  ]
}

    systemId is the path or the URL of the schema. IntelliJ-based editors map a namespace to a file under Settings, Languages & Frameworks, Schemas and DTDs: the URI is http://qemu-tool/fleet/1.0. Emacs' nXML mode reads RELAX NG's compact syntax only, so it wants the RELAX NG schema converted first (trang fleet.rng fleet.rnc) and a schemas.xml entry for the namespace.

    In a processing instruction before the root element, which the parser ignores and editors that follow the xml-model convention read. The href is wherever the schema is: a copy beside the fleet file here, or the Debian package's path. For the XSD:

    <?xml-model href="fleet.xsd"
            type="application/xml"
            schematypens="http://www.w3.org/2001/XMLSchema"?>
<fleet xmlns="http://qemu-tool/fleet/1.0">
  ...
</fleet>

    And for the RELAX NG schema, in an editor that takes one:

    <?xml-model href="fleet.rng"
            type="application/xml"
            schematypens="http://relaxng.org/ns/structure/1.0"?>

    None of the editor setups has been tried here. What has been run is the parser on a file that carries each processing instruction, which it accepts, and on one with xsi:schemaLocation, which it refuses.

    What the schema cannot check¶

    A file that validates can still be refused. Either schema describes one file and one element at a time; these rules are the parser's and the generator's alone. What is said of the schema here holds for both; the XSD also lets by what is listed above.

    In one file, refused by the parser:

    • two <server> entries with the same id;
    • a <devices> block beside an <ernic-per-vm>, <rocjitsu-per-vm> or <sdxi-per-vm> that says another number than the block lists: the block replaces the three counts, so such a count would never apply;
    • text directly under <fleet>, <devices> or a <server>. The schema allows any text there, because the parser allows white space the grammar's own rule for element content would refuse;
    • an unclosed quote, a trailing backslash or a quoted word that spans lines in <vm-qemu-args>;
    • a character outside ASCII that is not a decimal digit, in an integer;
    • an integer or a port of more digits than Python's int() converts, which is 4300 unless Python is told otherwise. The parser reports it as not an integer; a grammar does not count that far.

    And a validator may answer differently from the parser for a reason that is the validator's own and not the grammar's:

    • a <!DOCTYPE> whose internal subset gives an attribute a default (<!ATTLIST server type CDATA "ernic">), in either direction. The parser applies the default, so a <server> with no type loads, and a default on <fleet> is refused as an attribute. A validator sees the attribute only if it applies such defaults: lxml does not unless its parser is made with attribute_defaults=True, and then it agrees with the parser;
    • a <!DOCTYPE> whose internal subset declares an entity that holds an element (<!ENTITY e "<vm-count>2</vm-count>">, then &e; under <fleet>). The parser accepts it, and so do jing and Xerces. libxml2 (xmllint, lxml) leaves that element out of the fleet namespace and both schemas then refuse it. An entity that holds text only is read the same way by all of them;
    • an integer with thousands of single underscores between its digits. A validator built on Java's regular expressions, jing for one, recurses once for each underscore and ends in a StackOverflowError, which is no answer at all: seen with 2000 underscores, not with 1000, at Java's default stack size. The parser accepts such an integer up to int()'s limit, and so does libxml2 with either schema;
    • a value of hundreds of thousands of characters in an element the schemas give a pattern. Xerces, the XSD validator of Java and of many editors, takes time that grows with the square of the length there: seconds for 200,000 characters. Its answer is the right one when it comes.

    No shipped file has a <!DOCTYPE>.

    Across files given as layers:

    • a later file overrides the flat elements it sets, whole;
    • <devices> entries merge by id: an entry for an id an earlier layer has changes what it names and keeps the rest, a new id is appended, and no layer can remove one;
    • an id cannot change type in a later layer;
    • a per-VM count set in a layer after a <devices> block, to another number, is an error. qemu-tool check reports these as a layers merge line.

    Per-VM lists, checked when a stack is generated:

    • <vm-shm-size>, <rocjitsu-config> and <vm-filesystem> take one value for every guest, or a comma list of exactly <vm-count> values. Any other length is an error;
    • <vm-extra-hostfwd> is the exception: its commas are several rules for one guest, and the whole value goes to every guest.

    Rules between elements, checked by gen-compose (gen_compose.py):

    • <vm-count> of at least 1, and <ernic-per-vm> and <rocjitsu-per-vm> of at least 1, or a <devices> block with at least one ernic and one rocjitsu server;
    • at most one spdk server a guest, and <spdk-image> set when there is one;
    • <sdxi-image> set when a guest has an SDXI device;
    • <qemu-ref>, <ernic-ref> and <rocjitsu-ref> not empty, on one build stamp, with one libvfio-user revision between QEMU and the servers;
    • the tag <backing-ref> names, and how it relates to <publish-ref> and <image-allow-guest-lag>;
    • the fleet's size: at most 64 NICs on the mesh and 244 NICs in all, with a warning above 40 on the mesh;
    • <vm-nvme-vram> and <vm-pci-mmio-bridge> need <vm-nvme> of at least 1, and <vm-nvme-block-size> of 4096 a <vm-nvme> other than 0;
    • <ernic-mtu> other than 1500 is refused when <vm-qemu-args> already passes a credential of the name it uses, and noted when it is under 4192 or <ernic-tap> is false.

    And nothing checks a value the parser passes through as text: a size, a duration, an image reference, <p4-guest-scope>, a server option's value. Those reach docker, QEMU or the device server as written.
